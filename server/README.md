# DROPLY signaling server

The current desktop app connects automatically. Users share their device codes, add friends and approve incoming transfers; normal onboarding does not require an invitation or administrator.

## Run and deploy

From server/, run npm ci then npm start. On Render, keep the existing service and URL, select waterme1on7r-byte/Droply on main, set Root Directory to server, Build Command to npm ci and Start Command to npm start. Preserve existing environment variables and the existing Neon database when moving repositories.

Environment variables:

- DATABASE_URL: the Neon PostgreSQL connection string, stored only in Render's secret environment. TLS certificates are verified outside localhost.
- ADMIN_TOKEN: a random server-only administrator token of at least 32 characters, used for recovery and revocation. Never package it with the desktop app or put it in Git.
- PORT: supplied by Render.
- ALLOW_LEGACY: set false when older clients have migrated. The current deployment temporarily uses true to preserve older clients.
- KEY: optional legacy compatibility key; unused by current desktop clients. Do not add a guessed key to an existing unkeyed deployment.

The existing production deployment has no KEY variable and explicitly permits unkeyed legacy access during migration. Registered device identities remain protected from legacy impersonation. Changing repositories must preserve this setting; retiring legacy access is a separate coordinated rollout after older users upgrade.

Render Free local files are ephemeral, so production uses Neon Free PostgreSQL. AUTH_STORE_FILE is only a local single-process alternative on persistent storage. Do not replace a damaged production database with a blank store.

## Automatic registration

POST /auth/register accepts an installation ID and random per-device credential generated by the client. The app saves the credential with Electron safeStorage before registration and reuses it on retries. The server stores only a SHA-256 hash. A matching registration is idempotent; a different credential cannot replace an identity or revive a revoked device. Existing credentials, device codes, friends and profiles survive the repository migration.

Registration is limited to 10 requests per transport IP per minute, 200 globally per hour and 10,000 stored devices. These limits suit the current small deployment. Connected group presence is visible to connected devices; accepted friends and receiver approval control transfers. File bytes travel over WebRTC, not through PostgreSQL.

## Administrator recovery

Invite endpoints remain available for exceptional recovery and older clients. Set DROPLY_ADMIN_URL to the HTTPS server origin and DROPLY_ADMIN_TOKEN in a local shell, then use:

- node admin.js devices
- node admin.js invite DRP-XXXX-XXXX-XXXX
- node admin.js invite DRP-XXXX-XXXX-XXXX --replace
- node admin.js revoke DRP-XXXX-XXXX-XXXX

Replacement invitations expire, are bound to one device code and are one-use. Revocation disconnects the device and prevents reconnection. Do not share administrator credentials with users.

## Security and tests

Signaling fixes the sender identity from the authenticated connection and limits rates, payloads, output buffering and authentication time. PostgreSQL transactions and a row lock protect shared authentication state. Bearer credentials can still be stolen by malware running as the same OS user, and this protocol does not hide group presence or add signatures to WebRTC offers.

Run npm test from this directory. GitHub Actions additionally starts PostgreSQL to verify atomic concurrent enrollment across store instances. Local integration checks have exercised two native Electron devices, real WebRTC transfers, restart persistence and revocation. A deployed migration must also verify /auth/status and device connectivity before deleting the old server repository.
